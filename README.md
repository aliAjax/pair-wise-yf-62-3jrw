# 海上搜救联合指挥

源提示词摘要：按海域划设搜索区，协调船艇、直升机、无人机和岸上观察点，记录任务变更、通信与天气影响；离线单位恢复后合并状态，过期位置必须明确提示，并提供低带宽模式。

## 技术栈

Next.js 15、TypeScript、App Router、Mantine、Zustand、TanStack Query、React Hook Form、Zod、next-intl、date-fns、MapLibre。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62027`

## 可用流程

- 搜索区从规划、执行到关闭，范围变更一律走**范围修订单**，不再直接覆盖当前范围。
- 船艇、直升机、无人机可调派、转入失联、恢复在线。
- 任务单支持新建议题、分配单位、关闭任务和事件留痕。
- 离线模拟与低带宽模式可切换；本地数据由 Zustand persist 保存。

## 范围修订单规则

- **提交锁定版本**：修订单提交时记录所采用的海况预报版本（`SEA-*`）与通信窗口版本（`COMM-*`），版次随单留痕。
- **换版退回重算**：预报或通信窗口换版后，所有仍在队列、尚未执行的修订自动置为“退回重算”，须按最新版本重提；已生效修订、已完成任务与航迹留档均不改写。
- **先写入为准**：两名指挥员对同一片区域同时提交时，先写入的一单算准；后到单标记为“并发拒收”，界面给出两版范围的逐边差异、先写入单指挥员与版次，再按最新版重提。
- **执行只改范围**：修订生效时只更新搜索区边界与版次，正在执行的任务与单位位置保持不变。
- **通知送达队列**：每单按任务参与单位与岸上观察点生成送达记录；发送失败（离线/单位失联）时修订仍留在队列。回网后只重试未送达的部分，已送达不重发；也可按单位单条补送。修订在通知全部送达前不会执行。
- **完成留档**：任务关闭时按当时的搜索区边界生成范围快照、按各单位最后位置（含过期标注）生成航迹留档，地图以灰色虚线与灰/橙点展示，不随后续修订移动。
- **低带宽**：先看每单的版次/状态/送达一行摘要，细节折叠；地图停用，通信窗口只显示窗口数量。
- **地图**：地图只初始化一次，范围或单位变化走增量同步，不再因区域调整而重建、连带重置单位标记。
